Proof of concept · English → Telugu dubbing

Making the mouth and the meaning agree

A working pipeline that turns an English discourse into Telugu — translated, re-voiced, and fitted to the original speech timings — in six shipping configurations, four of which run on a laptop for free.

47 tests passing end-to-end run verified audio + video modes: runnable now lip-sync: needs a 24 GB GPU branch claude/sadhguru-telugu-lipsync-poc

The problem

Sync is won in the translation, not in the lip-sync model

“Translate the video into Telugu” sounds like one problem. It is three, and they pull against each other.

Saying the same thing (semantic), saying it in the same number of seconds (temporal), and having the mouth make those sounds (visual). The third one gets all the attention and is the least important. A viewer forgives a soft mouth. A viewer does not forgive a sentence still running after the speaker has visibly stopped.

The measured reason: a faithful Telugu rendering of English discourse runs about 1.2× longer in spoken time. Our test run came out at 1.21× before fitting. Translate first and think about timing later, and every sentence overruns — by the time a diffusion model is redrawing frames, the timing is already decided.

So this pipeline hands the translator a syllable budget per line, predicts each line's spoken duration before synthesising it, and fits the result into the original speech slots.

Architecture

One pipeline, three exits

The six use cases are not six pipelines. They are the same nine stages with the later ones switched off — which is why the cheap configurations cost about a minute per video-minute and only the last one needs a GPU. Every stage caches to disk, so you iterate on the fast stages and run lip-sync once.

Measured

What the aligner actually did

From a real end-to-end run on a 29-second clip: six utterances, 23.5 s of speech. The Telugu came out 28.5 s — 1.21× the English — and the aligner had to place all of it back inside the original slots.

The quality gate

Thresholds come from ITU-R BT.1359-1: viewers detect desync when audio leads the picture by 45 ms, but tolerate 125 ms of lag. A 3:1 asymmetry — in the physical world, sound always arrives after the sight of the event. So the aligner will pad the end of an utterance but never steal its start. 

$ python -m telugu_dub run --video clip.mp4 --mode video

[dub] fit: 0 natural, 2 in-band, 1 borrowed pause, 3 hard, 1 overflow
[dub] QC REVIEW: 83.3% of 6 segments inside the ITU-R BT.1359 window
      mean |drift| 0.05s, p95 0.3s, max 0.3s

      segments to fix: [1] (shorten the Telugu, or split the slot)

This run does not pass, and that is the point — the gate caught a real defect on a six-line clip. Nothing should be sent to lip-sync until it passes, or you spend hours of GPU time rendering a mouth that moves at the wrong moments.

Every stage is a swappable provider. The free column needs no GPU, no key and no HuggingFace login — it exists so the first run happens today.

Run it

Four commands to your first Telugu clip

  1. Install

    Creates a venv and installs the free stack. ffmpeg is the only thing worth having system-wide.

    ./scripts/setup.sh && source .venv/bin/activate
export PYTHONPATH=src

  2. Check the machine

    Prints one line per requirement for the mode you picked, with the exact install command for anything missing.

    python -m telugu_dub doctor --config config/free_cpu.yaml --mode video

  3. Get 60–90 seconds

    Not the full talk. You will iterate three or four times. Pick a clip where the speaker talks to camera in one continuous take.

    ./scripts/fetch_youtube.sh "https://youtube.com/watch?v=ID" 120 210

  4. Dub it — audio first

    Audio mode is the fastest loop and it is where you judge the translation. Then the video run reuses everything cached.

    python -m telugu_dub run --video samples/source.mp4 \
    --config config/free_cpu.yaml --mode audio --voice preset

python -m telugu_dub run --video samples/source.mp4 \
    --config config/free_cpu.yaml --mode video --voice preset

Read qc.json before anything else

High overflow_pct or over_speed_pct means the Telugu is running past its slots — calibrate the speaking rate (scripts/calibrate_rate.py), or switch the translator to an LLM. Named failing_segments are audibly out of sync; edit their text_tgt in manifest.json and re-run with --force tts align render mix.

Risk

What will go wrong

The beard

Every open-source lip-sync model inpaints a mouth region learned mostly from clean-shaven faces. Facial hair produces the classic failure: a smeared mouth, or one that floats over the beard. This is the single biggest visual risk in the project, and it must be tested on a real clip before committing to a model. It is also the strongest argument for shipping mode video first.

Everything else

  • Dub finishes after the speaker stops — translation too long. Tighten the budget or split the segment; do not compress harder.
  • Speech sounds rushed — tempo above 1.15×. Retranslate shorter.
  • Mouths appear on the audience — lip-sync applied to cutaways. Gate on face detection per shot.
  • Sanskrit terms mangled — the translator "helpfully" translated them. Pin them in the glossary.
  • Voice drifts between segments — inconsistent TTS reference. One fixed reference clip per video.

Favourable, for once

Slow, pause-heavy delivery gives the aligner elastic to borrow. Long single-camera takes are the regime lip-sync models were trained on. Monologue means no diarization and no cross-talk. This is one of the easier dubbing targets — apart from the beard.

Rights

The part that decides whether this ships

The footage is copyrighted, and dubbing it is a derivative work. Cloning a real person's voice needs that person's consent — several jurisdictions now treat voice as a protected personal attribute, and this is a recognisable public figure speaking on spiritual matters, where a fabricated statement does real damage.

Note what a cloned voice changes: a stock voice reads as “this is a dub”, while his own voice saying a mistranslated sentence reads as “he said that”. The stakes on translation quality go up, not down.

A defensible POC: a short excerpt, kept internal, labelled as an AI translation, in a neutral Telugu voice until consent for cloning exists. That is exactly what --voice preset gives you. The realistic path to production is a partnership — which also gets better source material than a YouTube rip.
